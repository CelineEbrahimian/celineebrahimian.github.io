Upper-Body Force-Feedback Exoskeleton

Humanoid teleoperation · Started at Minerva Humanoids, continuing as my FYDP
Mechanical designWiring & schematicsMotor-control firmwareCAN busUser testing
In progress · FYDP

What

A wearable upper-body exoskeleton for teleoperating a humanoid robot. It relays the robot's contact forces back to the operator's arms, so they can feel what the robot is doing and control it more accurately.

How

  • Owned the full design and build: mechanical, wiring diagrams and schematics, and motor-control firmware
  • Built an arm fixture with an elbow motor controlled over CAN bus to test force feedback on real users
  • Ran user tests to find the maximum safe torque and the smallest torque change people could feel, which set the motor requirements
  • Built and wore the first arm: backpack frame, harness, and shoulder and elbow joints

Lessons so far

  • Test with people before choosing hardware; user tests set the motor requirements
  • How noticeable a force change is depends on the force already applied, so feedback can't use one fixed step size
  • For a wearable, fit and comfort matter as much as performance

Search & Rescue Robot: Motor Control

Autonomous robot · Raspberry Pi 5
C++PythonOpenCVPWM + encodersMultithreadingSolidWorks
Watch it run

Line following, zone detection and gripper control in action.

▶ Project video

What

A fully autonomous robot that follows a line with OpenCV, detects the target and safe zones, and uses a gripper to move the target, inside a 0.22 × 0.22 × 0.25 m envelope. Scored on speed and successful runs out of 3.

How

  • Sized and sourced the drive motors from design calculations
  • Wrote C++ motor firmware (PWM + encoder feedback) for differential drive and the gripper
  • Closed-loop wheel-velocity P-controller, with vision, control and motor loops on separate threads
  • Replaced an unreliable IMU with encoder-based state estimation and motion primitives (precise distance, in-place turns, active braking)
  • Built a Python logging and plotting tool to tune 40+ control parameters
  • Designed drive-system parts in SolidWorks

Lessons

  • Start firmware early; late integration caused the biggest delays
  • Simple beats complex: encoders outperformed the IMU
  • Real dynamics need empirical tuning, not just calculation
  • Most bugs were system-level (hardware × firmware), not isolated

Two-Axis Gantry Embedded Control System

Embedded control & safety · STM32
CSTM32Interrupts & timersADC / UARTOscilloscope

What

The full control and safety system for a two-axis gantry: I/O design, schematic, potentiometer motor input, and positioning repeatable to within 1 cm.

How

  • Configured GPIO and memory-mapped I/O to drive motors and read limit switches
  • Replaced polling with interrupt- and timer-based motion control, then simplified the interrupt structure to remove callback conflicts
  • Fail-safe normally-closed limit switches with automatic motor-reverse recovery
  • ADC readings logged over UART (PuTTY); verified on hardware with an oscilloscope and step-by-step motion tests

Lessons

  • Interrupts beat polling for real-time control
  • Build fail-safes into hardware and software from day one
  • Simpler interrupt structures mean fewer timing bugs
  • Hardware bring-up finds timing, noise and I/O issues fastest

Plant Maintenance Robot

Autonomous mobile robot · LEGO EV3
C / C++Color sensingActuationFault handling

What

A robot that identifies plant types by color and gives each one its own water dose, with basic safety and fault handling.

How

  • Custom EV3 chassis with a winch-driven spray mechanism
  • Color sensing to classify each plant and choose travel direction
  • Dosing algorithm linking classification to motion and actuation
  • Fault stops and safety logic written in C/C++

Lessons

  • How sensing, decisions and actuation combine into autonomy
  • Fault handling matters even at small scale
  • Turning high-level behavior into embedded logic
